## 1 · Historia

**Como** Encargado de Reposición  
**Quiero** modificar un artículo y administrar sus códigos alternativos  
**Para** corregir errores de carga y sumar códigos nuevos que aparezcan en facturas

## 2 · Precondiciones

El artículo existe y está activo (HU-ART-01)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el artículo está activo y los datos son válidos | cuando el usuario guarda los cambios | entonces el sistema actualiza el registro | + | Pendiente |
| **CA-002** | Dado que el usuario agrega un código alternativo con su proveedor | cuando el usuario guarda | entonces el sistema lo asocia al artículo sin alterar los códigos existentes | + | Pendiente |
| **CA-003** | Dado que el código alternativo que se intenta agregar ya pertenece a otro artículo | cuando el usuario intenta guardarlo | entonces el sistema lo rechaza e informa el conflicto | − | Pendiente |
| **CA-004** | Dado que el usuario modifica los márgenes de venta | cuando el usuario guarda | entonces el sistema recalcula el precio de venta estimado únicamente de ese artículo | + | Pendiente |
| **CA-005** | Dado que el artículo está dado de baja | cuando el usuario intenta modificarlo | entonces el sistema deniega la operación e indica que debe reactivarse | − | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

El recálculo del precio estimado nunca alcanza al catálogo completo (ver HU-ART-05).
