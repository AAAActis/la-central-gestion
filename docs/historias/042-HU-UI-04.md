## 1 · Historia

**Como** Usuario del sistema  
**Quiero** consultar cualquier entidad con un mismo mecanismo de búsqueda y navegación  
**Para** no tener que aprender una forma distinta de buscar en cada módulo

## 2 · Precondiciones

La API expone los endpoints de consulta de las entidades

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el usuario ingresa un criterio de búsqueda | cuando ejecuta la consulta | entonces el sistema muestra los resultados coincidentes | + | Pendiente |
| **CA-002** | Dado que la consulta no arroja coincidencias | cuando se completa la búsqueda | entonces el sistema muestra el mensaje de sin resultados y no una tabla vacía | − | Pendiente |
| **CA-003** | Dado que existen registros dados de baja | cuando el usuario habilita la opción de incluir inactivos | entonces el sistema los incorpora al listado, diferenciados visualmente | + | Pendiente |
| **CA-004** | Dado que el resultado supera la cantidad de filas visibles | cuando se muestra el listado | entonces el sistema pagina los resultados sin traer la totalidad de los registros | + | Pendiente |

**Cantidad de criterios: 4.**

## 4 · Notas

Componente base del que dependen HU-UI-07 a HU-UI-10. Construirlo bien una vez convierte las pantallas posteriores en configuración y no en código nuevo.
