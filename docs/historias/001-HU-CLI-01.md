## 1 · Historia

**Como** Vendedor  
**Quiero** dar de alta un cliente con sus datos de identificación y contacto  
**Para** poder facturarle y tener trazabilidad de sus operaciones

## 2 · Precondiciones

El vendedor cuenta con sesión iniciada (HU-ACC-01) · Existe el padrón de clientes

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que no existe ningún cliente con el CUIT/CUIL ingresado | cuando el vendedor confirma el alta | entonces el sistema registra el cliente en estado activo y lo muestra en el listado | + | Pendiente |
| **CA-002** | Dado que ya existe un cliente con el mismo CUIT/CUIL | cuando el vendedor intenta confirmar el alta | entonces el sistema rechaza la operación y muestra el CUIT/CUIL duplicado | − | Pendiente |
| **CA-003** | Dado que existe un cliente con la misma Razón Social pero distinto CUIT/CUIL | cuando el vendedor confirma el alta | entonces el sistema registra el cliente y muestra una advertencia de posible duplicado | + | Pendiente |
| **CA-004** | Dado que el campo CUIT/CUIL o Nombre/Razón Social está vacío | cuando el vendedor intenta confirmar el alta | entonces el sistema bloquea el guardado e indica qué campo obligatorio falta | − | Pendiente |
| **CA-005** | Dado que el vendedor cargó dos teléfonos y dos direcciones | cuando el vendedor confirma el alta | entonces el sistema registra los cuatro datos asociados al cliente | + | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

Teléfonos y direcciones se modelan como entidades 1:N, no como columnas de la tabla Cliente.
