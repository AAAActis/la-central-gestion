## 1 · Historia

**Como** Encargado de Reposición  
**Quiero** Dar de baja un artículo discontinuado  
**Para** Que no pueda seguir facturándose, conservando su historial de operaciones

## 2 · Precondiciones

El artículo existe y está activo · El usuario conoce su existencia actual (HU-STK-01)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el artículo tiene existencia cero en ambas ubicaciones y el usuario ingresó el motivo | cuando el usuario confirma la baja | entonces el sistema lo marca como inactivo conservando su historial | + | Pendiente |
| **CA-002** | Dado que el artículo tiene existencia mayor a cero en alguna ubicación | cuando el usuario intenta darlo de baja | entonces el sistema bloquea la operación e informa la cantidad y la ubicación de lo que queda | − | Pendiente |
| **CA-003** | Dado que el artículo tiene existencia y el usuario declara que se trata de un error de actualización de stock | cuando el usuario confirma la baja | entonces el sistema la ejecuta y registra esa declaración junto al motivo | + | Pendiente |
| **CA-004** | Dado que el código interno reescrito no coincide | cuando el usuario intenta confirmar | entonces el sistema rechaza la operación | − | Pendiente |
| **CA-005** | Dado que el artículo está inactivo | cuando el usuario intenta agregarlo a una factura de venta o de compra | entonces el sistema no lo ofrece entre las opciones | − | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

Decisión pendiente: un tercer estado «discontinuado» (no se compra más pero se vende hasta agotar) no fue incorporado. Con dos estados, el artículo permanece activo hasta llegar a cero.
