## 1 · Historia

**Como** Encargado de reposición  
**Quiero** administrar artículos con sus códigos por proveedor y sus márgenes  
**Para** mantener el catálogo que sostiene el comparador y la carga de facturas

## 2 · Precondiciones

HU-UI-04 y HU-UI-05 implementadas · Épica 3 disponible en la API

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el usuario abre el detalle de un artículo | cuando se carga la ficha | entonces el sistema muestra sus códigos alternativos con el proveedor de cada uno, sus márgenes, el precio de costo y el precio de venta estimado | + | Pendiente |
| **CA-002** | Dado que el usuario agrega un código ya asignado a otro artículo | cuando intenta guardar | entonces el sistema muestra el rechazo indicando a qué artículo pertenece | − | Pendiente |
| **CA-003** | Dado que el usuario busca por un código alternativo | cuando ejecuta la consulta | entonces el sistema devuelve el artículo al que ese código pertenece | + | Pendiente |
| **CA-004** | Dado que el artículo tiene existencia mayor a cero | cuando se intenta darlo de baja | entonces el sistema informa la cantidad y ubicación, y exige la declaración de error de stock para continuar | − | Pendiente |

**Cantidad de criterios: 4.**

## 4 · Notas

Es la pantalla más compleja del CRUD: administra tres colecciones anidadas (códigos, márgenes y existencias) sobre un mismo formulario.
