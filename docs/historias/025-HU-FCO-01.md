## 1 · Historia

**Como** Encargado de Administración  
**Quiero** registrar manualmente una factura de compra con su detalle  
**Para** dejar asentada la compra y actualizar stock, costo e historial en una sola operación

## 2 · Precondiciones

El proveedor existe y está activo (HU-PRO-01) · Los artículos existen y están activos (HU-ART-01)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el proveedor está activo y la factura tiene al menos una línea | cuando el usuario confirma | entonces el sistema registra la factura, incrementa el stock, actualiza el último proveedor comprado y el precio de costo, y agrega el registro al historial | + | Pendiente |
| **CA-002** | Dado que el número de factura ya existe activo para ese proveedor | cuando el usuario intenta confirmar | entonces el sistema lo rechaza e informa la factura con la que colisiona | − | Pendiente |
| **CA-003** | Dado que la factura no tiene líneas de detalle | cuando el usuario intenta confirmar | entonces el sistema bloquea la operación | − | Pendiente |
| **CA-004** | Dado que el usuario registró fecha de emisión, fecha de vencimiento y retenciones | cuando se confirma la factura | entonces el sistema los almacena como parte del registro, sin lógica financiera asociada | + | Pendiente |
| **CA-005** | Dado que se actualiza el precio de costo de un artículo con márgenes cargados | cuando finaliza el registro | entonces el sistema recalcula su precio de venta estimado | + | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

Retenciones y vencimiento se almacenan como datos del comprobante. No generan reportes ni alertas (Mandato v4, Fuera de Alcance).
