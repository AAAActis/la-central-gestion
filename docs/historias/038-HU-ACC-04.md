## 1 · Historia

**Como** Usuario del sistema  
**Quiero** que mi sesión se cierre cuando dejo el puesto  
**Para** que nadie opere con la identidad de mi puesto y cada operación quede correctamente atribuida

## 2 · Precondiciones

El usuario tiene una sesión iniciada (HU-ACC-01)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el usuario tiene sesión activa | cuando selecciona la opción de cerrar sesión | entonces el sistema la cierra y vuelve a la pantalla de acceso | + | Pendiente |
| **CA-002** | Dado que la sesión lleva 12 horas iniciada | cuando el usuario intenta operar | entonces el sistema la da por expirada y solicita autenticarse nuevamente | − | Pendiente |
| **CA-003** | Dado que hay una carga en curso sin confirmar | cuando la sesión se cierra o expira | entonces el sistema descarta la carga sin persistir datos parciales | − | Pendiente |
| **CA-004** | Dado que un usuario ejecuta una operación que modifica datos | cuando finaliza la operación | entonces el sistema la registra asociada al puesto que la ejecutó, con fecha y hora | + | Pendiente |
| **CA-005** | Dado que un usuario anula una factura o da de baja un registro | cuando completa la operación | entonces el sistema guarda el motivo ingresado junto con el puesto responsable | + | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

Consecuencia asumida: como el usuario identifica al puesto y no a la persona, la trazabilidad alcanza a la computadora desde la que se operó, no a quién operó. Es coherente con la operatoria actual de Multisoft.
