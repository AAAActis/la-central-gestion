## 1 · Historia

**Como** Encargado de administración  
**Quiero** subir el PDF de la factura y revisar lo que el sistema interpretó  
**Para** confirmar la carga sabiendo exactamente qué dato reconoció bien y cuál debo verificar

## 2 · Precondiciones

HU-FCO-05 disponible en la API · HU-UI-05 implementada

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el usuario adjunta un PDF válido | cuando finaliza el procesamiento | entonces el sistema muestra el formulario de revisión con todos los campos editables | + | Pendiente |
| **CA-002** | Dado que un dato fue interpretado con baja certeza | cuando se muestra la revisión | entonces el sistema lo señala visualmente para que el usuario sepa dónde mirar | + | Pendiente |
| **CA-003** | Dado que una línea tiene un código no reconocido | cuando se muestra la revisión | entonces el sistema la marca como no resuelta y ofrece la redirección al alta de artículo | − | Pendiente |
| **CA-004** | Dado que quedan líneas sin resolver | cuando el usuario intenta confirmar | entonces el sistema mantiene deshabilitada la confirmación e indica cuántas faltan | − | Pendiente |
| **CA-005** | Dado que el procesamiento del archivo demora | cuando el usuario espera | entonces el sistema muestra el avance en lugar de una pantalla sin respuesta | + | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

La interfaz es la que materializa el control humano exigido por el mandato: sin la señalización de certeza y el bloqueo por códigos sin resolver, la automatización deja de ser supervisada.
