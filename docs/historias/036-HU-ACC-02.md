## 1 · Historia

**Como** Administrador  
**Quiero** dar de alta, modificar y dar de baja los usuarios del sistema  
**Para** controlar qué puestos acceden y con qué identidad queda registrada cada operación

## 2 · Precondiciones

El Administrador cuenta con sesión iniciada (HU-ACC-01)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el nombre de usuario no existe | cuando el Administrador confirma el alta | entonces el sistema registra el puesto con su sucursal, rol y contraseña inicial | + | Pendiente |
| **CA-002** | Dado que el nombre de usuario ya existe | cuando el Administrador intenta darlo de alta | entonces el sistema rechaza la operación | − | Pendiente |
| **CA-003** | Dado que el Administrador da de baja un usuario | cuando se consultan operaciones anteriores de ese puesto | entonces el sistema sigue mostrando su identidad en el historial | + | Pendiente |
| **CA-004** | Dado que es el único Administrador activo | cuando intenta darse de baja a sí mismo o cambiar su rol | entonces el sistema bloquea la operación para no dejar el sistema sin administración | − | Pendiente |
| **CA-005** | Dado que el usuario olvidó su contraseña | cuando el Administrador la restablece | entonces el sistema aplica la nueva contraseña sin requerir la anterior | + | Pendiente |
| **CA-006** | Dado que el usuario tiene una sucursal asociada | cuando inicia una operación de stock | entonces el sistema propone esa sucursal como ubicación por defecto | + | Pendiente |

**Cantidad de criterios: 6.**

## 4 · Notas

Modelo definido por el equipo: los usuarios representan puestos de trabajo (venta01, venta02, sb01, sb02), no personas, replicando la operatoria actual de Multisoft.
