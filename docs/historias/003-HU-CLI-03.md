## 1 · Historia

**Como** Vendedor  
**Quiero** modificar los datos de un cliente ya registrado  
**Para** corregir errores y facturar con información correcta

## 2 · Precondiciones

El cliente existe y está activo (HU-CLI-01) · El vendedor lo localizó por CUIT/CUIL (HU-CLI-02)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el cliente está activo y los datos ingresados son válidos | cuando el vendedor guarda los cambios | entonces el sistema actualiza el registro y muestra los datos modificados | + | Pendiente |
| **CA-002** | Dado que el vendedor vació un campo obligatorio o ingresó un tipo de dato inválido | cuando el vendedor intenta guardar | entonces el sistema bloquea el guardado e indica el campo con error | − | Pendiente |
| **CA-003** | Dado que el CUIT/CUIL ingresado ya pertenece a otro cliente | cuando el vendedor intenta guardar | entonces el sistema rechaza el cambio e informa a qué cliente pertenece | − | Pendiente |
| **CA-004** | Dado que el cliente tiene teléfonos y direcciones cargados | cuando el vendedor agrega, edita o quita uno de ellos | entonces el sistema aplica el cambio sin alterar el resto de los datos | + | Pendiente |
| **CA-005** | Dado que el cliente está dado de baja | cuando el vendedor intenta modificarlo | entonces el sistema deniega la operación e indica que debe reactivarse primero | − | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

Depende de HU-CLI-05 para el caso de clientes inactivos.
