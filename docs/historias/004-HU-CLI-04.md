## 1 · Historia

**Como** Vendedor  
**Quiero** dar de baja un cliente que ya no opera con la empresa  
**Para** sacarlo de las búsquedas diarias conservando su historial de operaciones

## 2 · Precondiciones

El cliente existe y está activo · El vendedor cuenta con permiso de baja

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el vendedor reescribió correctamente el CUIT/CUIL e ingresó el motivo | cuando el vendedor confirma la baja | entonces el sistema marca el cliente como inactivo y conserva su registro y sus facturas | + | Pendiente |
| **CA-002** | Dado que el CUIT/CUIL reescrito no coincide con el del cliente | cuando el vendedor intenta confirmar | entonces el sistema rechaza la operación y no ejecuta la baja | − | Pendiente |
| **CA-003** | Dado que el campo motivo de baja está vacío | cuando el vendedor intenta confirmar | entonces el sistema bloquea la operación e indica que el motivo es obligatorio | − | Pendiente |
| **CA-004** | Dado que el cliente fue dado de baja | cuando el vendedor intenta seleccionarlo en una nueva factura de venta | entonces el sistema no lo ofrece entre las opciones disponibles | − | Pendiente |
| **CA-005** | Dado que el cliente dado de baja tiene facturas históricas | cuando se consulta cualquiera de esas facturas | entonces el sistema muestra correctamente los datos del cliente asociado | + | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

La baja es lógica: el registro nunca se elimina de la base de datos.
