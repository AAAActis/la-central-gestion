## 1 · Historia

**Como** Usuario del sistema  
**Quiero** que el sistema me exija confirmar y justificar las operaciones irreversibles  
**Para** no dar de baja ni anular un registro por error

## 2 · Precondiciones

HU-UI-05 implementada

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el usuario solicita una baja o una anulación | cuando se abre la confirmación | entonces el sistema exige ingresar el motivo; **si la operación no se puede deshacer** (anular un comprobante), exige además reescribir la clave del registro | + | Pendiente |
| **CA-002** | Dado que el motivo está vacío o, cuando se exige, la clave reescrita no coincide | cuando el usuario intenta confirmar | entonces el sistema no ejecuta la operación e indica el campo con su error | − | Pendiente |
| **CA-003** | Dado que el usuario cancela | cuando se cierra la confirmación | entonces el sistema no ejecuta ninguna acción | − | Pendiente |

**Cantidad de criterios: 3.**

## 4 · Notas

Implementa el criterio transversal de baja lógica: confirmación con clave reescrita más motivo obligatorio.
