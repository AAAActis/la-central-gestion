## 1 · Historia

**Como** Usuario del sistema  
**Quiero** recibir un aviso claro cuando algo falla  
**Para** saber si debo reintentar, corregir un dato o avisar a alguien

## 2 · Precondiciones

HU-UI-03 implementada

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que la API devuelve un error de regla de negocio | cuando se recibe la respuesta | entonces el sistema muestra el motivo en lenguaje del negocio, no el mensaje técnico | − | Pendiente |
| **CA-002** | Dado que la API no responde | cuando se agota el tiempo de espera | entonces el sistema informa que no hay conexión con el servidor y ofrece reintentar | − | Pendiente |
| **CA-003** | Dado que una operación se completa correctamente | cuando finaliza la llamada | entonces el sistema muestra una confirmación breve que no interrumpe el trabajo | + | Pendiente |

**Cantidad de criterios: 3.**

## 4 · Notas

Ningún mensaje mostrado al usuario debe exponer rutas, nombres de tabla ni trazas de la excepción.
