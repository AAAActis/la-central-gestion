## 1 · Historia

**Como** Vendedor  
**Quiero** anular una factura de venta  
**Para** dejar sin efecto una operación que no se concretó, devolviendo la mercadería al stock

## 2 · Precondiciones

La factura existe y está en estado activo · El vendedor tiene permiso de anulación

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que la factura está activa y el vendedor ingresó el motivo | cuando el vendedor confirma la anulación | entonces el sistema la marca como anulada y devuelve la existencia a la ubicación de origen | + | Pendiente |
| **CA-002** | Dado que el motivo de anulación está vacío | cuando el vendedor intenta confirmar | entonces el sistema bloquea la operación | − | Pendiente |
| **CA-003** | Dado que la factura fue anulada | cuando se intenta registrar una nueva factura con ese mismo número | entonces el sistema lo permite: el número queda liberado | + | Pendiente |
| **CA-004** | Dado que la factura ya está anulada | cuando el vendedor intenta anularla o modificarla nuevamente | entonces el sistema deniega la operación | − | Pendiente |
| **CA-005** | Dado que falla la devolución de existencias a mitad del proceso | cuando se ejecuta la anulación | entonces el sistema revierte la operación completa y deja la factura en estado activo | − | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

La anulación es la única vía de corrección: el sistema no contempla notas de crédito (Mandato v4).
