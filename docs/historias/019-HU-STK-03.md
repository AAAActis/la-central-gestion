## 1 · Historia

**Como** Vendedor  
**Quiero** que el stock baje automáticamente al registrar una factura de venta  
**Para** que las cantidades registradas reflejen la mercadería realmente entregada

## 2 · Precondiciones

Existe la funcionalidad de registro de factura de venta (HU-FVE-01)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que se confirma una factura de venta con la ubicación de salida seleccionada | cuando finaliza el registro | entonces el sistema descuenta la cantidad de cada artículo en esa ubicación | + | Pendiente |
| **CA-002** | Dado que la cantidad vendida supera la existencia de esa ubicación | cuando el vendedor confirma la venta | entonces el sistema la registra igualmente y la existencia queda en negativo | + | Pendiente |
| **CA-003** | Dado que la ubicación de salida no cubre la cantidad pero la otra ubicación sí | cuando el vendedor carga la línea | entonces el sistema informa que la otra ubicación dispone del faltante para que se solicite desde allí | + | Pendiente |
| **CA-004** | Dado que ninguna ubicación cubre el faltante | cuando el vendedor confirma la venta | entonces el sistema la registra igual: el faltante se resuelve comprándole al proveedor con entrega posterior | + | Pendiente |
| **CA-005** | Dado que el vendedor no seleccionó ubicación de salida | cuando el vendedor intenta confirmar | entonces el sistema bloquea la confirmación | − | Pendiente |

**Cantidad de criterios: 5.**

## 4 · Notas

Decisión de negocio: la falta de stock nunca bloquea la venta. Observación asumida: el stock negativo no distingue una venta contra pedido de un error de carga; diferenciarlos requeriría marcar la línea como «contra pedido», hoy fuera de alcance.
