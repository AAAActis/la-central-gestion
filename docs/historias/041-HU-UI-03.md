## 1 · Historia

**Como** Usuario del sistema  
**Quiero** que la aplicación gestione mi sesión de forma transparente  
**Para** no tener que autenticarme en cada operación y que nadie use mi sesión si dejo el puesto

## 2 · Precondiciones

La API emite y valida el token de sesión (HU-ACC-01, HU-ACC-04)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el usuario tiene sesión activa | cuando realiza cualquier operación | entonces el sistema adjunta el token a la llamada sin intervención del usuario | + | Pendiente |
| **CA-002** | Dado que la sesión expiró | cuando el usuario intenta operar | entonces el sistema lo redirige a la pantalla de ingreso e informa que la sesión venció | − | Pendiente |
| **CA-003** | Dado que un usuario sin sesión escribe directamente la dirección de una pantalla interna | cuando intenta acceder | entonces el sistema lo redirige a la pantalla de ingreso | − | Pendiente |
| **CA-004** | Dado que el usuario cierra sesión | cuando se completa la operación | entonces el sistema descarta el token y no permite volver atrás para seguir operando | + | Pendiente |

**Cantidad de criterios: 4.**

## 4 · Notas

Implica interceptor de peticiones y guarda de rutas. Es la HU de mayor riesgo de la épica: un fallo acá compromete la seguridad de todo el frontend.
