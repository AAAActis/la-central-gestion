## 1 · Historia

**Como** Usuario del sistema  
**Quiero** que la aplicación gestione mi sesión de forma transparente  
**Para** no tener que autenticarme en cada operación y que nadie use mi sesión si dejo el puesto

## 2 · Precondiciones

La API emite y valida el token de sesión (HU-ACC-01, HU-ACC-04)

## 3 · Criterios de aceptación

| ID | Dado que | Cuando | Entonces | Tipo | Prueba |
|---|---|---|---|---|---|
| **CA-001** | Dado que el usuario tiene sesión activa | cuando realiza cualquier operación | entonces el sistema adjunta el token a la llamada sin intervención del usuario | + | **Pasa** · `sesion.spec.ts`: «CA-001 · con sesión activa, toda llamada a la API lleva el token…» y «CA-001 · el login no lleva token» (caracterización: ya se cumplía desde B1) |
| **CA-002** | Dado que la sesión expiró | cuando el usuario intenta operar | entonces el sistema lo redirige a la pantalla de ingreso e informa que la sesión venció | − | **Pasa** · `sesion.spec.ts`: «CA-002 · un 401 con la sesión vigente la cierra…», «un 403 no cierra la sesión», «el 401 de un token anterior no cierra la sesión nueva»; `app.spec.ts`: «CA-002 · si la API rechaza el token vencido, vuelve al ingreso e informa…»; `login.spec.ts`: «CA-002 · si la sesión anterior venció…». La expiración se detecta por el 401 de la API: el token no se decodifica en el navegador (B1). |
| **CA-003** | Dado que un usuario sin sesión escribe directamente la dirección de una pantalla interna | cuando intenta acceder | entonces el sistema lo redirige a la pantalla de ingreso | − | **Pasa** · `app.spec.ts`: «CA-003 · sin sesión, escribir la dirección de una pantalla interna lleva al ingreso» y «sin sesión muestra el login y no muestra el menú» (caracterización: ya se cumplía desde B1). El ingreso se muestra en la misma dirección; al entrar, el usuario queda en la pantalla que pidió. |
| **CA-004** | Dado que el usuario cierra sesión | cuando se completa la operación | entonces el sistema descarta el token y no permite volver atrás para seguir operando | + | **Pasa** · `sesion.spec.ts`: «CA-004 · Salir descarta el token: no queda guardado y una recarga no lo recupera» y «CA-004 · después de Salir, las llamadas salen sin token»; `app.spec.ts`: «CA-004 · después de Salir, volver a la pantalla anterior no deja seguir operando»; en Chrome real, `history.back()` después de Salir muestra el acceso (`docs/sprint04/evidencia/hu-ui-03/mediciones-cdp.txt`). |

**Cantidad de criterios: 4.**
